## Failure diagnosis and remediation decisions

The exact pinned framework archive contains Windows-style external module specifiers in **all four rebuilt production App Router bundles**, 14 `next\\dist` prefixes each. [Static archive receipt](./external-trial-38964204005/package-portability-review.json) verifies the archive SHA and bundle bytes. The upstream build configuration's `externalHandler` uses host `path.relative(...)` directly in emitted CommonJS requests. On Windows that produces backslashes; same-environment byte reproducibility did not establish Linux portability. The Linux require stack confirms the actual production renderer consumes these bytes.

Recommended next package repair: normalize **generated module specifiers in the source build configuration**, regenerate all four bundles and their source maps through the pinned recipe, and extend patch/provenance identities to include that configuration change. Add package-admission regressions against platform-dependent specifiers and the relevant external-handler paths. Then repeat bounded cold local packaging/reproduction and focused SRI/browser checks before proposing a new Linux candidate. Do not patch installed dependencies, rewrite bundled HTML, replace strings in opaque output, remove maps or relax an assertion. **No repair or rebuild was performed after this trial.**

The evidence workflow also needs local regressions for failures before runtime: initialize every evidence directory independently, retain build stdout/exit code, complete the manifest despite skipped stages, and validate available builder counters even when compilation fails. Preserve exact failed assertions and independent restart/cache checks. These are proposed repairs; this trial's incomplete artifact is kept unchanged.

[Affected packages, installed/fixed versions and all 54 high rows](./external-trial-38964204005/ADVISORIES.md) and [machine-readable dispositions](./external-trial-38964204005/ADVISORIES.json) remain visible. The four historical critical package/advisory pairs are absent from the **fresh base** scan, which now reports zero critical; this does not establish final-image remediation. Trixie still fails the base threshold. Scanner `status: fixed` means a fixed version is available, not that the installed package is fixed.

The 11 Node-package findings are in bundled npm/Yarn dependencies. Reported fixes include brace-expansion 2.1.6, ip-address 10.3.1, pacote 21.5.1, picomatch 4.0.4 and sigstore 4.1.1; http-cache-semantics 4.2.0 has no reported fix. Prefer a supported upstream manager/base update or a separately auditable base without unused managers. Removing managers only from the final stage cannot clear the independently scanned base gate. No fixed Debian version is reported for the 43 high Debian findings. Await vendor updates or review a maintained minimal base with exact provenance and fresh complete scans. Applicability of systemd-homed, privileged mount/nsenter/ACL conditions, ncurses/perl and package-manager trust/cache paths needs review; no non-root applicability argument overrides the zero-high threshold.
