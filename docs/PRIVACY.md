## Assisted rights requests

The local register stores minimized case metadata and evidence hashes, not requester identity or message text. Keep originals, exports and the identity/business mapping in the private operator store. The register is in `%LOCALAPPDATA%\Ornigami\privacy-rights`; `node scripts/privacy-rights-register.mjs --help` lists current commands and accepted values.

1. Check monitored routes each business day and accept requests received through other support channels. Preserve the original privately and open a case using the true receipt time, request type and hash. Acknowledge within one business day; the CLI's 24-hour reminder is local and sends no notification.
2. Verify identity and authority proportionately; scope the request to the correct person/business and protect others' data. Keep uncertain identity/scope unresolved with a reason and review date. Distinguish Ornigami-controller requests from assistance to a customer controller; securely notify that business, record its instructions and preserve the original response deadline.
3. Assess account/application data, provider copies, private exports, logs and backups. Choose a scoped access/export, correction, restriction/objection or erasure outcome and assess exceptions record by record. Do not promise that an app export contains every provider copy.
4. Preserve suppression, trial eligibility and unresolved-operation safeguards. A local case hold does not create a database retention hold; a database hold requires a separately reviewed target-scoped change. Pause affected cleanup while changing holds.
5. Self-service deletion is disabled. Do not invoke it, run ad hoc production DELETEs, cancel subscriptions or revoke tokens merely because a case opened. Provider-pending work remains held/unresolved; do not blindly retry or claim completion. Any destructive or provider action needs separate scoped review and an execution receipt.
6. Respond securely. Normal response is within one calendar month. A necessary extension may add up to two months, with reasons communicated within the first month. Record the communicated extension deadline privately; the register does not compute it or send reminders. For a refusal, provide reasons and supervisory-complaint/judicial-remedy information within the response period.
7. Complete only after identity, documented outcome and the safeguard receipts are recorded. Review held/unresolved cases by their due date; provider-pending cases need a documented provider outcome before clearing.

Command templates below require real timestamps, evidence and review; they are not authorization or receipts:

```powershell
node scripts/privacy-rights-register.mjs open-case --received-at '<zoned ISO timestamp>' --type access --evidence-sha256 '<request hash>'
node scripts/privacy-rights-register.mjs update-case --case-id '<returned UUID>' --state identity_review --identity-verified yes --evidence-sha256 '<verification hash>'
node scripts/privacy-rights-register.mjs update-case --case-id '<UUID>' --state in_progress --preserved suppression,trial,unresolved --evidence-sha256 '<scope and safeguard review hash>'
node scripts/privacy-rights-register.mjs update-case --case-id '<UUID>' --state completed --outcome-documented yes --evidence-sha256 '<secure response and outcome hash>'
node scripts/privacy-rights-register.mjs update-case --case-id '<UUID>' --state unresolved --reason-code provider_pending --next-review-at '<future UTC ISO timestamp within 30 days>'
```

For unresolved provider work, leaving that state also requires `--provider-outcome documented` and its evidence hash. A communicated extension uses `--state extension_communicated` with the communication hash and is not completion. `cleanup` previews completed-case expiry; `cleanup --apply yes` removes only fully evidenced completed cases at least 365 days old. It does not remove active/held cases, routing receipts or the separate originals, mappings and exports; assess their expiry separately. See [EDPB rights guidance](https://www.edpb.europa.eu/sme/be-compliant/respect-individuals-rights_en).
