# A08 — Google route and provider contracts

Last updated: 2026-10-03

The API accepts an optional business selection in `businessId`. GET requests use the query string. POST requests may use the query string or a JSON body. If both are supplied, they must match. Empty, malformed, or explicitly null body IDs are rejected; conflicting query/body values return `400`. If the ID is omitted, A02 resolves its deterministic default business. An explicit invalid or unauthorized ID returns `403` and never falls back.

| Endpoint | Contract |
| --- | --- |
| `GET /api/google/connection?businessId=…` | Any authorized business owner/member can check the canonical owner's connection. Returns `{ connected: false, locations: [] }` when disconnected. When connected, includes owner discoveries for owners and only this business's selected location for members. Returns sanitized location metadata and `selected`; no tokens or raw payloads. |
| `POST /api/google/disconnect` | Empty body remains supported. An owner must resolve the business; members receive `403`. Deletes the integration owner's connection and invalidates every cached location for that owner atomically. Returns `{ ok: true, scope: "owner_google_connection" }`; the scope covers all businesses owned by that user. |
| `GET /api/google/oauth/start?businessId=…` | Owner-only and requires the existing A02 business entitlement for Replies or Booster (including its past-due grace). Redirects to Google and stores a ten-minute HttpOnly state cookie. A local debug request returns redirect URI metadata with the Google URL redacted. |
| `GET /api/google/oauth/callback?code=…&state=…` | Requires exact state-cookie equality, a valid signed actor/business/owner payload, current owner access, and current A02 business entitlement before exchange. Rechecks them before storage. On success, invalidates cached locations before saving the new encrypted owner credentials. Failure redirects to the existing Google connection page with a fixed reason; token values never enter the response. |
| `GET /api/google/locations?businessId=…` | Owner/member live discovery and cache sync. Requires the existing A02 business entitlement for Replies or Booster (including its past-due grace). The response preserves `name` and `locationName`, plus IDs, title, store code, place ID, and selection state. No auto-selection. |
| `GET /api/google/locations/list?businessId=…` | Reads the local cache without a provider call. Owners see their cached discoveries; members see only this business's selected location. Each item includes `selected`. |
| `POST /api/google/locations/sync` | Accepts optional `businessId` in query or JSON body; empty body is allowed. Requires the existing A02 business entitlement for Replies or Booster (including its past-due grace). Members may run shared discovery but receive only their selected location and its count; owner responses may include all owner discoveries. A complete successful discovery revalidates present rows and marks stale rows disconnected. |
| `POST /api/google/locations/selection` | Body: `{ "businessId": "<uuid>", "locationId": "<owner-cached-location-uuid>" }`; `businessId` may be omitted for A02's default. Owner-only, existing A02 business entitlement. Checks the cached owner location and confirms the exact canonical Google resource name in a live discovery before writing. It rechecks the connection generation and conditions the mapping write on that same generation. Same-ID selection is idempotent; switching an existing different selection returns `409`. |
| `POST /api/google/reviews/sync` | Body may include `businessId` and `locationName`. Requires active `review_replies` access. A member may sync only the selected location; omitted `locationName` resolves to that selection. A supplied nonselected or malformed location is rejected before provider access. |
| `POST /api/google/replies` | Body: `{ "businessId", "reviewId", "locationName", "reply" }`. Requires active `review_replies` access and the selected location. Before calling Google, checks the exact business/location/review tuple in local storage. Reply text is limited to 4096 UTF-8 bytes. |

Business authorization errors use JSON and `401`/`403`. Conflicting or invalid request shapes return `400`. A missing/disconnected selection, changed connection generation, or attempted switch returns `409`. Google verification/provider failures return a generic `502`. An unavailable selected-location table or selection storage failure returns a generic `503`; SQL details are not returned. These endpoints do not read a member's personal plan or Google credentials.

`getSelectedGoogleLocation(context, requestedName?)` is the provider-boundary helper for A08/A09 callers. It returns the selected owner-cached row only when the canonical owner's connection exists and the row's `connection_version` matches the current connection. A malformed or nonselected requested canonical name returns `403`; an absent, disconnected, or stale selection returns `409`; unavailable selection/version storage returns `503`. It never chooses the first discovered location. `listBusinessGoogleLocations(context)` scopes member output to the business mapping. `syncBusinessGoogleLocations(context)` captures the owner's connection version before provider requests, checks it again after discovery, writes cache rows only if the same version remains current, and applies the visible-count rule for members.

## Provider requests

OAuth asks for the `business.manage` scope. Discovery first paginates Account Management `accounts.list` (`pageSize=20`) and then requests each `accounts/{accountId}/locations` collection through Business Information v1 with `readMask=name,title,storeCode,storefrontAddress,metadata,categories` and `pageSize=100`. It carries each `nextPageToken`, validates provider resource names, removes duplicate canonical location names, and has a 200-provider-request overall budget. `placeId` and `newReviewUri` come from location metadata; the manual Booster URL is not changed.

Reviews use the Reviews API v4 resource `accounts/{accountId}/locations/{locationId}/reviews`, following every returned `nextPageToken` up to the local page cap before persisting. Google documents `pageSize` up to 50. The current default cap is 20 pages (at most 1,000 reviews per request); when a location exceeds that cap, the route fails the full sync without persisting a partial fetch. Resumable large-location sync is a follow-up for A12/A13. Provider `429`/`503` errors map to retryable responses and may carry a bounded numeric `Retry-After`; other provider errors map to `502`. Replies use `PUT accounts/{accountId}/locations/{locationId}/reviews/{reviewId}/reply` with JSON `{ "comment": "…" }`. The token-aware client only sends bearer requests to the configured Google HTTPS origins, decrypts stored credentials, upgrades legacy plaintext rows on read, refreshes expiring tokens, and applies bounded timeouts/retries.

Official Google references:

- [Account Management `accounts.list`](https://developers.google.com/my-business/reference/accountmanagement/rest/v1/accounts/list)
- [Business Information `accounts.locations.list`](https://developers.google.com/my-business/reference/businessinformation/rest/v1/accounts.locations/list)
- [Reviews `accounts.locations.reviews.list`](https://developers.google.com/my-business/reference/rest/v4/accounts.locations.reviews/list)
- [Reviews `accounts.locations.reviews.updateReply`](https://developers.google.com/my-business/reference/rest/v4/accounts.locations.reviews/updateReply)

The review API's `pageSize` cap is 50, even though location discovery accepts 100. Keep exact-request mocks aligned with the official method-specific limits.

## Integration gates

The routes depend on A02's `BusinessContext` and business entitlement reader. The per-business selection table and `connection_version` columns are only proposed in [A08-selected-location-schema.sql](./A08-selected-location-schema.sql); A00 must number and install them after choosing backfill policy. Related proposals are [A08 canonical-resource/backfill](./A08-canonical-resource-backfill.sql) and the [A08 review-sync handoff](./A08-google-review-sync-handoff.md). A13 owns selection UI/client scoping. A07 must decide how a selected location's Google review URL feeds Review Booster while preserving manually entered URLs. A09 owns review processing policy, reply settings, and usage/draft changes. A11 owns remote Google revocation/privacy cleanup. A16 owns API approval and real-provider acceptance.

Credential replacement rotates the proposed connection version; token refresh preserves it. A delayed sync from an old connection version cannot authorize its cache rows after reconnect. Refresh persistence compares the connection version and original encrypted token snapshot before updating, so concurrent refresh or OAuth replacement cannot overwrite newer credentials. Refresh coalescing remains process-local, so duplicate refresh calls may still occur across workers.
